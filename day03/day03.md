# 二、Data Race

## 1. 什么是 Data Race

Data Race，中文叫“数据竞争”。

当满足下面几个条件时，可能产生 Data Race：

- 有多个线程。
- 多个线程访问同一个共享数据。
- 至少有一个线程会修改这个数据。
- 线程之间没有正确的同步措施。

例如：

多个线程同时修改同一个 counter。

这种情况下，不同线程的操作可能互相干扰。


## 2. Data Race 的核心定义

面试口述：

Data Race 是多个线程在没有正确同步的情况下，
同时访问同一个共享数据，
并且至少有一个线程进行了写操作。

在 C++ 中，Data Race 会导致 Undefined Behavior，
也就是未定义行为。


## 3. 什么是 Undefined Behavior

Undefined Behavior：

未定义行为。

意思不是：

“结果一定错。”

而是：

C++ 标准不再保证程序会出现什么结果。

可能表现为：

- 结果错误。
- 每次运行结果不同。
- 程序崩溃。
- 出现其他不可预测行为。


# 三、为什么 counter++ 会产生 Data Race

## 1. counter++ 看起来是一行代码

但是从理解并发问题的角度，
它可以看成多个步骤：

1. 读取 counter。
2. 计算 counter + 1。
3. 把结果写回 counter。

所以 counter++ 不能简单理解为：

“绝对不可被打断的一步操作”。


## 2. Lost Update

Lost Update：

丢失更新。

例如：

counter 原来等于 100。

线程 A 读取到 100。

线程 B 也读取到 100。

线程 A 计算得到 101。

线程 B 也计算得到 101。

线程 A 写回 101。

线程 B 再写回 101。

虽然两个线程都执行了一次自增，
最终 counter 却只增加了 1。


## 3. 为什么每次运行结果不一样

线程的调度顺序不是固定的。

操作系统什么时候运行线程 A、
什么时候切换到线程 B，
每次运行都可能不同。

因此线程之间发生竞争的位置也不同。

所以 Data Race 经常表现为：

同一个程序每次运行得到不同结果。


## 4. 实验现象

两个线程各执行 100000 次 counter++。

理论期望结果：

200000。

没有同步时：

结果可能明显小于 200000，
并且每次运行结果不同。

加入正确的 mutex 同步之后：

结果可以稳定得到 200000。


# 四、共享数据

## 1. 什么是共享数据

多个线程都可以访问的数据，
叫做共享数据。

例如：

全局变量 counter。

如果多个线程都能够读取和修改 counter，
counter 就属于共享数据。


## 2. 共享数据不一定有问题

多个线程共享数据本身不是错误。

真正危险的是：

多个线程并发访问共享数据，
并且存在写操作，
却没有正确同步。


# 五、Critical Section

## 1. 什么是临界区

Critical Section：

临界区。

临界区是：

访问或修改共享资源，
并且不能让多个线程同时执行的代码区域。


## 2. 本次实验中的临界区

counter++ 是对共享变量 counter 的修改。

因此对 counter 的修改区域属于临界区。


## 3. 临界区的核心原则

同一时间：

只允许一个线程进入临界区。

这样可以避免多个线程同时修改共享数据。


# 六、Mutex

## 1. mutex 是什么

mutex：

Mutual Exclusion。

中文：

互斥锁。


## 2. mutex 的作用

mutex 用于保证：

同一时间只有一个线程能够进入被保护的临界区。


## 3. mutex 的基本思想

线程 A 获得 mutex。

线程 B 想获得同一个 mutex。

如果 mutex 当前已经被线程 A 占用：

线程 B 必须等待。

线程 A 释放 mutex 后：

线程 B 才有机会继续执行。


# 七、mutex 最容易理解错的地方

## 1. mutex 不是给变量自动加保护罩

mutex 并不会自动知道：

“我要保护 counter。”

mutex 真正做的是：

控制线程进入某段代码区域的权限。


## 2. 所有线程必须使用同一个 mutex

例如：

线程 A 修改 counter 前加锁。

线程 B 修改 counter 时完全不加锁。

这种情况仍然是不安全的。


## 3. 为什么仍然不安全

因为线程 B 可以直接绕过 mutex，
与线程 A 同时访问 counter。


## 4. 正确原则

如果多个线程会并发访问同一个共享状态，

那么访问这个共享状态的相关线程，
必须遵守同一套同步规则。

通常意味着：

使用同一个 mutex。


# 八、mutex 保护的到底是什么

不要说：

“mutex 锁住了线程。”

更准确的说法是：

mutex 用于保护共享资源对应的临界区。

或者：

mutex 用于控制多个线程对共享资源的互斥访问。


# 九、Data Race 与 Race Condition

当前阶段重点掌握 Data Race。

Data Race：

重点是多个线程无同步地访问同一内存位置，
并且至少存在一个写操作。

Race Condition：

范围更广，
指程序正确性依赖于线程执行时序。

当前阶段先把 Data Race 掌握扎实。


# 十、Day03 并发部分必须会背的回答

## 问题 1：什么是 Data Race？

答：

Data Race 是多个线程在没有正确同步的情况下，
同时访问同一个共享数据，
并且至少有一个线程进行了写操作。

C++ 中 Data Race 会导致未定义行为。


## 问题 2：为什么两个线程同时 counter++ 会出错？

答：

因为 counter++ 从并发角度不能简单看成不可分割的一步。

它包含读取、计算和写回过程。

两个线程可能同时读取旧值，
最后互相覆盖更新，
从而产生 Lost Update。


## 问题 3：为什么每次运行结果可能不同？

答：

因为线程调度顺序不确定。

每次运行时，
线程发生交错执行的位置不同，
因此竞争结果也可能不同。


## 问题 4：mutex 解决什么问题？

答：

mutex 通过互斥访问，
保证同一时间只有一个线程进入临界区，
从而避免多个线程同时修改共享数据。


## 问题 5：mutex 是不是自动保护某个变量？

答：

不是。

mutex 本身不会自动绑定某个变量。

所有访问共享资源的线程，
都需要主动使用同一个 mutex。


## 问题 6：一个线程加锁，另一个线程不加锁，安全吗？

答：

不安全。

因为没有加锁的线程可以绕过 mutex，
仍然可能和另一个线程同时访问共享数据。


## 问题 7：什么是临界区？

答：

临界区是访问或修改共享资源，
并且不能让多个线程同时执行的代码区域。


# 十一、LeetCode 104 二叉树的最大深度

## 1. 题目核心

求一棵二叉树从根节点到最深叶子节点的最大层数。


## 2. 递归核心思想

一棵树的最大深度等于：

左右子树最大深度中的较大值，

再加上当前节点这一层。


## 3. 递归三件事

写二叉树递归时，
可以先问三个问题：

1. 递归什么时候结束？
2. 左右子树分别返回什么？
3. 当前节点如何使用左右子树的结果？


## 4. LeetCode 104 的递归终止条件

如果当前节点为空：

说明这一部分没有节点。

深度为 0。


## 5. 左右子树分别返回什么

左子树递归返回：

左子树的最大深度。

右子树递归返回：

右子树的最大深度。


## 6. 当前节点如何得到答案

取：

左子树深度和右子树深度中的最大值。

然后：

+1。

这个 +1 表示：

当前节点本身这一层。


# 十二、为什么递归能够“回到上一层”

每一次函数调用都会保存自己的执行状态。

当前函数调用下一层递归时：

当前这一层暂时暂停。

下一层执行结束并 return 后：

程序会回到上一层原来暂停的位置继续执行。


## 1. 函数调用栈

递归依靠函数调用栈工作。

每次调用函数：

都会创建一个新的函数调用。

新的调用完成以后：

返回上一层调用。


## 2. 可以这样理解

先进入：

根节点。

然后进入：

左子树。

再进入：

更深的左子树。

到达空节点后：

开始逐层返回。

因此递归过程通常可以理解为：

先不断向下进入，

再逐层返回。


# 十三、LeetCode 104 必须会说的答案

## 问题 1：为什么空节点深度是 0？

因为空节点本身不存在，
所以不贡献任何树的层数。


## 问题 2：为什么最后需要 +1？

因为左右子树返回的只是子树深度。

当前 root 自己也占一层，

所以需要 +1。


## 问题 3：这道题为什么适合递归？

因为：

整棵树的最大深度问题，

可以拆成两个规模更小、结构相同的问题：

求左子树最大深度。

求右子树最大深度。


## 问题 4：递归为什么能够返回上一层？

因为每次函数调用都会保存在调用栈中。

子函数 return 后，
程序恢复上一层函数的执行状态并继续执行。


# 十四、Day03 易错点

## 易错点 1

认为 counter++ 是绝对不可分割的一步。

错误。

并发情况下，
必须考虑它可能包含读取、修改、写回等过程。


## 易错点 2

认为 Data Race 只会导致数值变小。

错误。

C++ Data Race 会导致未定义行为。


## 易错点 3

认为只要某一个线程加锁就安全。

错误。

访问同一共享状态的相关线程，
必须正确使用相同的同步机制。


## 易错点 4

认为 mutex 自动锁住变量。

错误。

mutex 控制的是临界区的互斥访问。


## 易错点 5

递归时忘记终止条件。

没有正确终止条件，
递归无法正常结束。


## 易错点 6

最大深度忘记加当前节点。

左右子树最大深度取最大值以后，
还需要 +1。


## 易错点 7

认为递归调用以后上一层函数消失了。

错误。

上一层函数状态保存在调用栈中，
下一层 return 后会继续执行上一层。
